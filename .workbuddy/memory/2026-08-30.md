# 2026-08-30

## 架构分析（KontainKeeper）
对全仓做了架构评审，报告输出至 `docs/architecture-review.md`。核心结论：

- **意图**：K8S vscode-server 容器 IDE 的直连管理，反向 WebSocket 通道，纯 stdlib agent（RSS<15MB），不依赖 K8S/宿主机，用户无感知。代码与 design.md 高度自洽，工程质量好。
- **三大 P0 风险（须先修）**：
  1. 阻塞式 SQLite（全局 threading.Lock）直接在 FastAPI async 事件循环里同步调用，规模化（M4 千连接）会卡；cleanup 聚合持锁重查询是延迟尖刺源。→ 建议 DB 写入移出 loop（aiosqlite 或 writer 线程队列）。
  2. `agent/entrypoint-wrapper.sh` 的 `exec $KK_ORIG_ENTRYPOINT` 未加引号词分割，基础镜像有显式 ENTRYPOINT 时启动失败；`scripts/build.sh` 的 `CMD ${ORIG_CMD}` 当 ORIG_CMD=null 时非法。
  3. `server/Dockerfile` 无 TLS，agent 用 wss 须前置反代；ws:// 直连会明文泄露 token，文档未强制。
- **P1**：agent 无 WS ping/keepalive、半开连接检测弱；黑名单子串匹配可绕过；登录无限流；批量命令非原子可能留孤儿 pending。
- **中**：单进程内存态 Hub 不可 HA；metrics_series 跨 24h 边界接缝；列表无缓存/分页。
